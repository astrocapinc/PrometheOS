# Operations, privacy and failure behavior

## Installation and supported environments

Windows 11 x64 on local NTFS is the primary live acceptance environment. Linux CI is secondary. macOS and other filesystems are unverified until tested; do not advertise universal support. Python core and built hub ship as a wheel with separate optional audio/provider extras, plus the A02 literature, local-AI and connector extras chosen at their checkpoints. Users do not need Node to run the wheel. Fresh install works without model credentials or any account. CP8 verifies uninstall leaves user research intact and upgrades back up before migration.

A04 (decision 0025) limits the current candidate's project source admission (spec/04) to Windows. On POSIX, original-source admission returns `unsupported`, so project open, reads and writes, maintenance, backup and migration do not work on Linux in this candidate. This is a regression against the required secondary Linux target, not a change of it: Linux is not an optional capability, cannot be classified not_applicable, and no Linux support is claimed while the refusal stands. A safe POSIX source admission, stated by a later reviewed amendment and backed by genuine Linux evidence, is a required repair before CP8; C08-INSTALL's Linux CI and the core regressions are neither waived nor narrowed. Earlier Linux or CP8 evidence for these paths cannot be carried forward.

Migrations are ordered, transactional where possible, version checked and tested from the previous supported schema. Before irreversible migration create a verified backup; failure leaves a recoverable old store and a clear diagnostic. Never downgrade by guessing SQL. Record supported version ranges and recovery commands.

## Local transport and path safety

Bind to 127.0.0.1/::1 only, reject unexpected Host and Origin, and require a paired session for all project data. Bootstrap a one-use high-entropy pairing token shown through the launching local CLI; exchange it through a same-origin form/body, never an URL query or access log. Token expires after five minutes and one use. Session cookie is HttpOnly, SameSite=Strict, short-lived; use an additional CSRF token for mutations and exact Origin checking. Under A07 (CP21):

- **The launch pairing.** `prometheos start` opens the browser with a one-use launch code in the URL fragment only (never a query, so it reaches no request line, Referer or server log). The page reads it, removes it from the current history entry with `history.replaceState` before any other request and exchanges it by a same-origin POST. It expires after 60 seconds, works once and is never printed to the terminal. Launch codes are issued only over the home's owner channel, which only the home's OS user can use: a named pipe whose ACL admits that user alone, or a per-home secret in a file readable only by that user, sent on a loopback request that a browser cannot make. No route reachable from a browser issues codes, and a request from another OS account or without the secret obtains none.
- **The home's own host name.** From CP21 the hub of a home is served at its own host name, `<home-id>.localhost`, on the home's fixed port. The Host allow-list admits that name; 127.0.0.1 and ::1 stay for non-browser clients.
- **The remembered-device credential.** A successful pairing may set a host-only cookie with a per-home name, set and accepted only on the home's own host name and port. The server rejects it unless Host, port and Origin are the home's own. It is high-entropy, HttpOnly and SameSite=Strict, stored in the home only as a digest, and expires after 14 days without use and 90 days at most. It is rotated each time it is exchanged for a new session, and the previous value stays valid for 60 seconds so that several open tabs or windows do not race. Revocation invalidates the current and the previous value at once. The owner can revoke it from the hub or the CLI. After a core restart it yields a new short-lived session without a new pairing; it never grants more than an owner session, an agent token can never use it, and a revoked, expired or unknown credential falls back to pairing.
- **Residual exposure.** Browsers do not isolate cookies by port. Another program serving the same host name on another port would receive the cookie; no other loopback host name receives it.
- **Same-user processes.** Any same-user process can run `start` or use the owner channel itself, and so obtain a launch code and an owner session. Same-user hostile processes are not excluded (below).
- **The PWA.** The pinned CSP adds `worker-src 'self'` and `manifest-src 'self'`. No wildcard CORS. Provider and service credentials stay out of browser storage and model context. No hub form or HTTP route accepts a credential value. The A03 credential-entry exception accepts a hidden prompt value or explicitly selected process environment value only within the same dedicated interactive local owner act; a supplied capability never permits piped or non-TTY entry. Entry may also use the provider's or OS's own interface; the hub shows credential references, health and the local entry command. Set a restrictive CSP and frame policy; sanitize Markdown and disable raw HTML. A local port alone is not authentication.

MCP stdio receives project-scoped capabilities through process setup, not prompt text. UI decision capability issuance is a separate owner route unavailable to agent tokens. Never accept arbitrary filesystem paths on a public read endpoint. Resolve approved root + normalized relative path, check final containment including symlinks/Windows reparse points, reject device/UNC paths outside approved policy, and recheck after opening when practical. Test traversal and race-resistant safe-open behavior on Windows. Same-user hostile process exclusion is not promised.

## Sensitivity, retention and deletion

Sensitivity order is normal < restricted < private. Derived output inherits the highest input level unless the owner explicitly approves a reviewed redaction. Normal agent contexts exclude restricted/private records, contact details, recordings and raw transcripts by default; explicit content selection plus egress policy is necessary. A local CLI response may reach a cloud coding agent, so “local” is not an egress exemption. Hub source views require the paired owner session and reveal exact source only on request.

Imports show what is retained, referenced, transmitted and unavailable. No hidden full-root indexing. Audit metadata contains IDs, operations and timestamps, not duplicate source text or secrets. Actor contacts are stored by reference. Log filters redact keys, authorization headers, filenames containing credentials and generated source excerpts; test actual logged output.

Logical archive/delete hides content without claiming erasure. A separate owner-authorized purge computes all affected payloads, excerpts, generated views, transcript derivatives, indexes, caches and media references. Shared blobs are deleted only after all references are removed or included in the purge. Remove sensitive body content from revisions and preserve only non-content tombstones; historical views explicitly show purged. Clear derived caches and vacuum/secure-delete as appropriate, with documented SSD/filesystem limitations. Never claim forensic erasure. External source files, exported archives, Git history and older backups are outside automatic purge; show an inventory and instructions rather than silently deleting them. Test that a unique canary string cannot be retrieved from live DB/API/context/cache after purge, while separately documenting physical remnants/backup limitations.

## Backups and maintenance

Use the architecture's SQLite backup + retained-media manifest. Maintenance lock acquisition is bounded and reports busy; OS-released lock recovers from killed process without manual unsafe force-unlock. Validate path/size/digest before archive extraction. Backup does not include reference-only bytes unless user explicitly adds them. Git tracks source code, not a complete research backup. Restore into a new store and show missing root bindings; never overwrite existing research or auto-bind an unrelated path.

Backup and migration read the source only through the guarded admission of spec/04 (A04). A healthy backup takes its snapshot with two connections inside one admission and ends that admission when both close, before hashing retained media and writing the archive; its maintenance lock still covers retained-media collection.

## Jobs and budgets

V1 schedules are interval in whole minutes (minimum 15) or weekly day/time in an explicit IANA zone. Persist due slots in UTC. For weekly DST: nonexistent wall times skip that occurrence; repeated times run at the first occurrence only. Tests pin both cases. A stopped machine may accumulate slots; default coalesces to one current digest/check and records skipped slots rather than flooding old notifications.

Each job slot has unique `(job_id,due_utc)`, state pending/running/succeeded/failed/unknown/skipped, lease owner/expiry, attempt count, input digest and result refs. Acquire transactionally; one active scheduler per project. Lease heartbeats update metadata without changing research content. A crash before side effects is retryable. An expired running slot with potentially completed paid/network side effect becomes unknown; do not automatically repeat. Fixed pure local handlers may retry up to three times with bounded backoff. No exactly-once guarantee across an external provider.

Budgets include max selected inputs, max tokens/output, max calls/run, max concurrent runs=1 and provider spending estimate cap. Report actual usage when available, never fabricate costs. Cancellation stops pending work and marks already transmitted data accurately. Notify only meaningful new findings, changed readiness, failure needing action or a decision; the hub inbox is default, external messages require explicit configuration and authorization.

## Compile engine and Git remotes (A01)

The TeX engine is a pinned Tectonic release. The owner installs it explicitly into the PrometheOS home; the binary digest is verified and nothing changes PATH or system configuration. Compile copies the selected workspace files into a staging directory and runs with shell-escape disabled, a wall-clock timeout, output-size limits and a bounded log. Only Tectonic's package-bundle fetch may use the network. That fetch is disclosed at install: its requests reveal which TeX packages, fonts and support files a document uses (not the manuscript text), and the bundle can be pre-cached so that an offline compile makes no request. CP9.1 verifies the actual fetch behaviour of the pinned release before this text is relied on. A LaTeX source is untrusted input: `\write18`, path escapes in `\input`/`\include` beyond the workspace, and oversized outputs are refused or contained, with tests.

Overleaf access uses the system `git` with Git Credential Manager. PrometheOS and agents never prompt for, read, log, store or place in URLs an Overleaf token, and credential-bearing remote URLs are rejected. Git commands run with explicit arguments, a timeout and a clean environment, and override every repository-local setting that can execute a program: hooks, `core.fsmonitor`, `core.sshCommand`, pagers, `diff`/`merge` drivers, clean/smudge filters, `core.askPass` and credential helpers other than the system Git Credential Manager configured outside the workspace. Push is an exact-plan owner capability, like other external transmission. Force-push and history rewriting are not offered.

## Network egress, adapters and telemetry (A02)

The core makes no network request on its own; every outbound path is an explicit, declared one. URL import, the CP6.3 provider, Tectonic's bundle fetch and Overleaf Git keep the rules stated for them above. The A02 adapters (discovery, connectors and remote model routes) are opt-in per project or workflow, show the destination and the exact query or data scope before the first request, and record what was sent, when, and any failure. Model and asset downloads are per user: each happens only on an explicit owner action that shows size, licence and location (see local models below).

- **Discovery adapters** for public scholarly APIs (candidates in spec/09) carry quota, rate limit, terms, contact requirement and retired endpoints as adapter metadata, rechecked at implementation rather than hard-coded as product promises. Calls stay within those limits, and cached records are kept only where the terms allow. No single source is presented as complete coverage.
- **Contact email.** The owner's address for polite access is a per-user owner setting stored outside project stores, exports, logs and contexts, together with an owner-approved list of services allowed to receive it. The initial list is Crossref and Unpaywall, as decision 0010 records. Adapter metadata may request an email, but that alone never sends it: the address goes only to approved services, only when discovery runs, and adding a service needs the owner's explicit approval. The discovery plan preview names the services that will receive it. An unapproved service gets requests without the address, or its adapter reports capability_unavailable if the service will not work without one.
- **No silent remote fallback, automatic model download or hidden telemetry.** A local failure reports unavailable; it never reroutes to a remote provider. Model and asset downloads happen only on an explicit owner action that shows size, licence and location. PrometheOS sends no usage data anywhere.
- **Offline.** With the network blocked after assets are installed, every declared local feature works, and discovery and remote routes report unavailable while local search and organisation continue.
- **The intelligence layer (A07).** Remote task runs are egress under the owner's standing policy (spec/04). Every request with project content asks for zero-data-retention endpoints and denies data collection. Only normal-sensitivity input is sent; restricted and private input never leaves under any policy and answers `policy_denied`. A file's sensitivity is the highest of its adoption root's (owner-set; restricted while unset) and of any record citing it, and bundles name files only by root alias and relative path. The reading model has no tools, its output is a closed typed structure checked in code, and quotes must re-read from the exact bytes, so text in a source cannot reach an operation or widen egress. Three spend layers apply: the key's own monthly limit set by the owner at the provider, the local monthly and per-run caps with reservations, and a per-task ceiling. An estimate is labelled as such, and billed cost replaces it when reported.
- **Quota and cost.** Per-workflow limits on records, pages, audio duration, calls, tokens, elapsed time, concurrency and disk are enforced before work. Spend reservations cover concurrent requests, and estimates are labelled as estimates. A quota pause keeps progress and does not charge again for completed stages on resume.

## Local models and heavy jobs (A02)

Model weights, tokenizers and language packs are installed under the PrometheOS home by explicit owner action, verified against a recorded revision hash, and can be imported offline from verified files. One heavy local job runs at a time under a configurable worker memory ceiling, and small tasks are batched. Inference and extraction run outside write transactions. Caches are keyed by input digest plus processing, model and rubric version, and only affected derivatives are invalidated. Removing a model removes only its assets and caches, never sources, records or decisions. Specific models need pinned revisions, licence review and hardware evaluation before they are offered. E11 measures latency, peak memory, disk, quality and cancellation on named CPU-only owner hardware with the app and ordinary desktop load present.

## Runs, approvals and recovery (A02)

Operation runs, approval requests and the maintenance service follow spec/04. Schedules still run only while the configured process or service is active. A closed chat or a restarted process never loses a run, an approval or an external execution record. Scientific job monitoring only observes externally owned runs. An owned runner, HPC scheduling, remote execution or automatic restart would need a separately reviewed scope and safety contract.

Recovery never overwrites a damaged store. The maintenance service works from the registry, store files and backup files; database probes and hot-journal recovery run only on copies. It reports a hot journal as `needs_journal_recovery` and preserves the original database and journal while recovering, verifying and restoring the copy into a new store. An agent restores only into a new PrometheOS-managed folder and may request a recovery switch only from a damaged registered store to such a verified replacement. Healthy-store rollback is an explicit owner `backup restore` action whose preview names current and backup sequences and the backup date. A store that needs migration or newer software follows that remedy rather than a recovery switch. An unreadable database digest gives typed `io_error` with no switch request or registry mutation until read access is restored; it is never replaced by an unreadable identity marker. The registry switches only after verification and quarantines the damaged store for inspection. Switch and migrate requests are held in the per-user registry until the owner grants them on the recovery screen or in an interactive session, with the action-specific bindings and at-most-once rules in spec/04. Migration rechecks health, refuses damaged stores and verifies its pre-migration backup before changing the store. An owner restore of a backup made at an older schema upgrades the verified staged copy along the migration chain, keeps the archive as its pre-migration backup and checks the upgraded copy before switching; a failed upgrade changes nothing (decision 0052). Tests use disposable corrupt stores.

Under A04 recovery follows the guarded source admission of spec/04 and its one classification precedence. No cached diagnostic, header hint or imitation of a SQLite writer lock authorises opening the original, and unknown or unavailable observations refuse. An unsupported journal mode gets structured nonopening diagnostics and the recovery pointer, but no journal recovery, switch or migration authority. Exact source bindings are checked and grants are spent while the operation's admission is held. Managed journal recovery classifies one guarded snapshot and copies the database and journal from it, with the retained media copied while that admission is held, before creating output.

## Untrusted content (A02)

Abstracts, PDFs, web pages, imported bibliographies, connector content, transcripts and model outputs are data. Their text cannot redefine workflow instructions, select or invoke tools, add operations to a pipeline, expand data access or egress, change a routing policy or manufacture an approval. These limits are enforced in code: pipelines run only declared operations, egress needs an existing opt-in, and authority comes only from capabilities. A model-based injection detector may supplement them, never replace them. Every checkpoint that reads outside text re-tests this boundary with hostile fixtures.

## Connectors (A02)

Coding-agent host, model provider and service connector are three distinct connections. A model key grants no calendar or file access, and PrometheOS never borrows a coding host's credentials. OAuth consent and credential entry happen in the provider's or the OS's own interface. Tokens live in the OS credential store and tools return only references and health. Each connector records remote IDs, versions or etags, cursors and tombstones, and assigns one owner per synchronised field. Disconnecting revokes local access and keeps permitted local records, marked stale. Google services and other APIs have quotas and possible charges: they are shown, and unapproved paid expansion stays disabled.

## Security and integrity acceptance

Threat fixtures cover malicious imported instructions, hostile package paths, unauthorized correction application, unpaired web access, CSRF/DNS-rebinding style Host requests, restricted context leakage, stale task submit, duplicate request and changed-key replay, concurrent writers, process death before/after commit, corrupted backup, missing media and purge remnants. A02 adds hostile abstracts, PDFs, pages, connector items and model outputs; forged, widened or cross-scope approval resumes; secret reads through any transport; offline runs with the network blocked; quota exhaustion mid-run; process death between run stages; cursor expiry; and a corrupt store recovered without overwriting. These are executable focused tests, not checklist claims. Claims about physical power loss, hostile same-user malware, cryptographic end-to-end encryption or regulatory compliance are outside v1.

Provider credentials use OS credential storage where available or process environment. Exported support bundles exclude research content by default and preview included paths. Pin dependency versions and capture license/security review at adoption and release. A scan does not prove no vulnerability; record tool/version/date and unresolved findings.

## Desktop application and agent package (A05)

- **Install and uninstall.** The desktop application installs per user without administrator rights and keeps its settings in the per-user PrometheOS home. Uninstall keeps project data and the registry.
- **The core sidecar.** The core runs as a sidecar bound to loopback, and the application stops it on quit.
- **Registered dependencies.** The shell framework and installer tooling are registered dependencies (spec/09).
- **No agent started by PrometheOS.** PrometheOS starts no agent process and registers no scheduled task, monitor or cloud routine that drains the queue or wakes an agent. Agents act when the researcher opens a session or asks.
- **Long runs started by the researcher.** A long run the researcher starts explicitly is an ordinary durable run. Whether such a loop may continue unattended is decided by a later amendment.
- **Host configuration.** The agent package changes host configuration only through its opt-in setup, and records what it wrote so it can be removed.
